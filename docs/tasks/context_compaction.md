# 上下文压缩可视化 + 手动压缩（/compact）

> 2026-09-20 grill 定案。词汇表见根目录 `CONTEXT.md`。

## 背景

自动压缩已有（摘要中间件，触发阈值/keep 走 `agent.summarization` 配置，`engine.py:627-631`），但用户看不到水位，只能被动等压缩；压缩过程提示是气泡里的灰色小字，不直观。手动触发没有入口。

## 定案

### 1. 手动压缩语义

- `/compact` 触发一次压缩，**不检查触发阈值**。
- 压多少：**默认沿用配置的 keep 策略**（和自动压缩行为一致），可带参数临时覆盖：
  - `/compact` → 按配置 keep 压
  - `/compact 5` → 只保留最近 5 轮
  - `/compact all` → 只保留最近 1 轮（最狠）
- 压缩对象是 langgraph checkpoint 里的线程状态；**业务库 `chat_ui_messages` 一条不动**，前端历史照常显示。
- 摘要模型沿用配置（可指定独立摘要模型的那套）。

### 2. 与生成中撞车

不做处理。前端流式期间输入框本来就锁定，天然挡住。
残留风险：REST 接口层面绕过前端直接调用无人拦截——自用产品，不为这个加锁。

### 3. 水位条

- 位置：聊天输入框正上方，3-4px 细条；只随会话显示（欢迎页不显示）。
- 内容：`当前窗口 tokens / context_limit`（如 `57k / 200k`），小字在条右侧。
- 分档：<70% 绿、70-90% 黄、>90% 红。
- 悬浮明细：本轮 input、缓存命中量、已压缩次数。
- 数据来源：当前会话最后一轮 `inputTokens / context_limit`（和 TokenUsagePanel「当前窗口」同口径）；会话消息无 usage 数据时隐藏整条。
- 压缩完成后不即时估算新水位，等下一轮 `llm_usage` 事件自然刷新。

### 4. 压缩入口（两个）

- 输入框输 `/compact [N|all]`——复用现有 `/` 拦截机制，作为内置命令项，本地拦截不发给模型。
- 水位条右端压缩图标按钮，点击等效 `/compact`。

### 5. 压缩过程可视化

- 压缩中：水位条动画；气泡处提示升级为「正在压缩…」。
- 完成：气泡处留「已压缩 N 条，保留 M 条」记录（复用现有 summarization_start/done 事件链路）。

### 6. 压缩分界线

- 压缩完成后，聊天历史区按条数画线：倒数第 kept 条消息上方插分隔显示「以下 34 条已压缩为摘要」样式（上方灰显、下方正常）。
- 位置按条数对齐计算，已知糙点：压缩和查看之间又发几轮可能偏一条，刷新自愈。可接受。

## 实现要点（开工时展开）

- 后端：新 REST 端点（如 `POST /api/sessions/{id}/compact`，body 可带 keep 覆盖），读 checkpoint 消息 → 复用摘要逻辑 → 重写线程状态；事件复用 `summarization_start/done/failed` SSE 链路。
- 前端：水位条组件、`/` 命令拦截加内置项、分界线渲染、压缩后重算水位。
- 自动压缩的触发阈值、keep 配置含义不变，本功能只是增加手动入口。
